**Game folder.** The dev install (`Mods\NativeMods\UE4SS\Mods\PalWorkPriority`

## What the extension does with our archive

Read in the source:

- The "root mod" installer (priority 15) claims any archive that has a path
  under a game top-level folder (`(^|/)pal(/|$)`, case-insensitive).
- It copies every file unchanged into the game root. Files without an
  extension are skipped.

Both our archives contain `Pal/Content/Paks/LogicMods/PalWorkPriority.pak`, so
the whole archive lands in the manual layout. Vortex's own UE4SS paths
(`Pal\Binaries\Win64\ue4ss`) are not used for it.

## Result

PASS: install, update and removal work through Vortex with the current
extension. Our archive lands in the manual layout and the mod loads. The
user's settings survive an update and a removal.

Notes for the Nexus page and changelog:

- Turn off "Manage modding requirements" when UE4SS comes from the game's mod
  loader or the Workshop. Otherwise Vortex installs a second UE4SS under
  `Pal\Binaries\Win64`.
- A game on another drive needs the staging folder on that drive (Vortex
  offers it with "Suggest").
- As on the Workshop route, edits in 0.4.1's `Scripts/config.lua` are lost
  when 0.4.1 is removed before 0.5.0 has run once.

Not covered:

- The "Mod manager download" button handoff (Chrome asks before opening
  Vortex).
- The real Nexus "update" flow from a published 0.5.0 file. It needs the
  published file; Vortex then replaces the old mod itself.
