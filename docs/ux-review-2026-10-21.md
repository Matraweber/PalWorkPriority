# Production Limits panel: new-user review, 2026-10-21

Related: [widget-spec](widget-spec.md) · [RELEASE-0.5.0](RELEASE-0.5.0.md) · [comment-ledger-2026-09-11](comment-ledger-2026-09-11.md) · [g3-escape-photo-death-2026-10-17](g3-escape-photo-death-2026-10-17.md)

Request (user, 2026-10-21): the limits panel must be readable and intuitive for
new users, plus Alt+F1/F2/F3 hints and a left/right-click legend on the stand
(Extramrdo). Method: a read-only code review of every user-visible string and
state (agent), checked against ten in-game screenshots taken 14:59-15:01 on rc1
(window 1276x720; panel states: rules with two legacy limits, picker, unavailable
item, search "ingot", Enter on a search, no results, Show all, amount editor,
Remove armed). **Nothing is changed yet: the user picks what gets done.**

Screenshot-confirmed observations: the stand legend is one tiny line under the
game's own "unused Stat Points" bar; "No item limit support" on every tile; a
no-result search shows empty column headers and no message; Remove's
confirmation does not say the limit cannot come back; Escape with an armed
Remove closes the whole panel (nothing deleted).

## P1: confuses or misleads a new user

1. **Nothing says 0.5.0 cannot create limits.** RELEASE says the UI says so
   before item selection; the code does not. "Browse items", "type to filter or
   click one" and "Choose an item to review its limit options" invite trying
   items, and each says "Unavailable: this item cannot have a separate
   production limit". Fix: empty state "No production limits yet.", RULES
   notice "Version 0.5.0 cannot create new limits. Per-item limits are planned
   for 0.6.", button "Browse items (view only in 0.5.0)", tile label "New limits
   in 0.6", ITEMS notice "0.5.0 cannot add new limits. Green items already have
   one: click to open it."
2. **Remove is permanent in 0.5.0 and the confirmation does not say so**
   (panel.lua:5738, says "Click Remove again" while the button reads "Sure?").
   Fix: "Click Sure? to delete this <Work> limit. 0.5.0 cannot add it back."
3. **Bug: "raise" lowers a large limit.** `step(current, -1)` returns the top
   rung (50,000) when the value is above every rung (panel.lua:4352-4358);
   right arrow / Enter on a typed 100,000 sets 50,000. Fix: keep the value and
   say it is above the highest step. Related: the unexplained 30,000 -> 50,000
   step in [g3-escape-photo-death-2026-10-17](g3-escape-photo-death-2026-10-17.md).
4. **Status column jargon and width.** "Group cap met / unmet", "Other limits
   unmet", "Met at N bases"; "cap" also means Pals per job elsewhere;
   "Other limits unmet" (225-254 px) overflows the 192 px column into Remove.
   Fix: "Below limit", "Limit reached", "Reached 2/3", "Others below",
   "No count yet", "Mod off", "Test mode"; optional hover explanation in the
   notice row.
5. **Legacy meaning hidden.** Only a 9 pt dim "Legacy group" under the job and
   a sub-line clause. Ore shows "No item limit support" while the Stone limit
   stops ore mining. Fix: row sub-label "Whole work type", picker label "Group
   limit applies", notice "Click a limit to type a new number. Each limit
   switches its whole work type.", drop the sub-line clause.
6. **"Server version incompatible" is easy to miss** (dim 12 pt; reason only on
   RULES). Fix: amber, reason "The server runs a different Pal Work Priority
   version. Install the same version as the server.", also on ITEMS.
7. **Right click silently lowers a limit and nothing explains the mouse.** Fix:
   the legend below.

## P2: friction

1. Editor prompt cut mid-sentence by `fit_name(..., 68)`; shorten only the name.
2. No warning when a new limit is already reached ("Saved. Storage already holds
   20,114 Stone, so the Mining limit is reached.").
3. Confirmations use raw ids and say "requested" on a host where it is saved.
4. "?" and "Unavailable" unexplained (counted every 10 s; Alt+F2 counts now).
5. Raw reason codes (handshake_timeout, queue_timeout, ...) reach the notice row.
6. Jargon in refusals ("output control", "producer adapter", "legacy rule").
7. Search box not focused although the notice says "type to filter".
8. Sub line can overflow with camp scope plus the install warning (105 chars).
9. "Base 1/3 (a1b2c3d4)" hex id means nothing to a player.
10. "Show all craftable items" is wrong for Wood, Stone, Berries.
11. Enter raises a rule one step instead of opening the type box (behaviour
    change, author's call).
12. "10.0M" shows a value above the 9,999,999 maximum.
13. (screenshot) A search with no results shows empty headers and no message.
14. (screenshot) Escape with an armed Remove closes the panel instead of
    disarming first.

## P3: polish

Repeated "Storage: Storage unavailable"; refusals in the cyan link colour;
9-10 pt dim labels under 4.5:1 contrast; item column cut at 16 chars; long
search text in the caption; lower-case notice starts and "ladder"; "No guild
for limits" wording; "Met at N bases" without total; save error hides the
Remove prompt; "Support unknown" detail jargon.

## Key hints and stand legend (requested)

- Tabs row: "ESC / ALT+F1" instead of "ESC"; host only "ALT+F2 RECOUNT NOW".
  Labels from the DarnMenu bindings (rebindable).
- RULES foot row (spare 34 px): "Left click a limit to type it, right click to
  lower it one step. Alt+F2 recounts storage now."
- Alt+F3 stays out of the panel (it only writes Stock.txt).
- Stand legend (ui.lua:111) in two lines: "Left click: toward 1   Right click:
  toward X   Or click a cell, then press 1-5 or X" and "1 highest, 5 lowest,
  X off   * sending   ! not saved   ? unknown   ALT+F1: Production Limits";
  stand header text stays the game's own.

## Wording to unify

limit vs ceiling vs cap; Alt+F11 named four ways; Alt+F2 "run a pass" (say
"re-check now"); Alt+F3 three ways; chat help line "how much of an item a base
stockpiles" is wrong for 0.5.0 and uses "authority"/"unfence".
