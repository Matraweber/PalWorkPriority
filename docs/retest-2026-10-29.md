## Dedicated server (GPortal "RAM") with this PC as client

- **Install:**
  - The old `Scripts` was renamed to `Scripts-before-6b6b9e1`.
  - `Scripts.zip` (files at its root) was unpacked with the panel's plain "UNZIP", which creates a folder named after the zip. "UNZIP HERE" would have put the files straight into the mod folder.
  - Result: 60 files. The sizes of main, panel, scheduler, item_sources, net, protocol, panel_status, caps, ui and darnmenu match the commit.
  - A first try with `pwp-server-scripts-6b6b9e1.zip` left a stray folder `pwp-server-scripts-6b6b9e1` (it only holds a `Scripts` copy). The mod does not load it.
- **Restart:** `PWP_READY version 0.5.0 … role authority settings available` at 00:35:19, with no warning.
- **Client:**
  - `pwp net` shows `sync: ready` on `protocol schema: 5`.
  - The client added Mining Stone 1. The server logged "Mining set Stone to 1 by a player".
  - With the panel open, the client got `server limit state: item_limits_on_rocks=true verdicts=1`. The row showed **"Limit reached"** where 0.5.0 before the fix showed "No count yet" (r11).
  - Removing it: the server logged "Mining Stone cleared by a player".
  - The server base had no stone rock left (mined out), so no rock was held there. Its Mining left the wanted list while the limit was reached, which is the per-base rule.
