# G1 upgrade from 0.4.1, 2026-10-11

Related: [RELEASE-0.5.0](RELEASE-0.5.0.md) · [restart-persistence-2026-10-11](restart-persistence-2026-10-11.md) · [release-replies-0.5.0-draft](release-replies-0.5.0-draft.md)

Gate: [RELEASE-0.5.0.md](RELEASE-0.5.0.md) G1 "Upgrade from 0.4.1 keeps every row".

## Offline: rc1 reads what 0.4.1 really wrote

`tests/test_upgrade_from_041.lua` loads 0.4.1's own `store`, `caps` and
`workdefs` (unmodified copies from tag v0.4.1 in `tests/fixtures/v041/`), lets
them write through their real `save()`, then loads the bytes with rc1. Every
priority row and every limit rule (including the `*` wildcard) is identical,
and loading does not rewrite either file. The fixture also pins 0.4.1's X loss.
Negative control: an rc1 reader that rejects priority 5 fails the test.

## Live: the manual (Nexus) archive over a real 0.4.1 install

1. Game closed through the menus. Whole mod folder snapshotted with a SHA-256
   manifest (4,323 files, identical) to
   `D:\PalWorkPriority-backups\pre-upgrade-test-20261011-220752`.
2. A faithful 0.4.1 install was put in place: tag v0.4.1's 23 Scripts and
   Info.json, its `Scripts/config.lua` with one marker (`interval_seconds = 11`),
   and the user's real priorities and limits **re-saved by 0.4.1's own code**.
   Fed 41 priority rows, 0.4.1 wrote 39: both X rows were dropped, the live
   reproduction of the bug users reported. No root config.lua (0.4.1 had none).
   Limitation: 0.4.1's own pak was not available, so the current pak stayed
   (the archive replaces it with identical bytes either way).
3. `tools/release.py` built the archives from 7de3037 (pak sha256 4eddf38b...).
   The manual archive was extracted into the game root as INSTALL.txt says:
   38 new files, 25 overwritten. Every 0.4.1 module was replaced; the only
   leftover in Scripts is the old `config.lua`, by design.
4. Launched through the AHK macro (scheduled task).

| Check | Result |

| boot | 0.5.0-rc1 loaded, PWP_READY settings=available, world up, first pass ran |
| config | new root `config.lua` carries `interval_seconds = 11`; `config.migration.bak` kept; status line says "every 11s" |
| priorities | all 39 rows identical to the 0.4.1-written file; file not rewritten |

| stand | draws the upgraded values (screenshot) |
| WARN/ERROR | 0 |

5. Game closed through the menus; everything restored from the snapshot. Only
   `remote.txt` differs (the remote channel the checks used). pak and mods.txt
   identical.

Evidence: `test-results/upgrade-041-20261011/` (0.4.1-written files, migrated
config, release manifest, stand screenshot); the post-upgrade state is kept in
the snapshot folder's `upgrade-result/`.

**Verdict: the manual upgrade route PASSES.** Not covered: the **Workshop**
