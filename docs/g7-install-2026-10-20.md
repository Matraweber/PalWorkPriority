# G7 install checks: clean installs and the Workshop/manual conflict, 2026-10-20

Related: [RELEASE-0.5.0](RELEASE-0.5.0.md) · [g1-workshop-2026-10-20](g1-workshop-2026-10-20.md) · [upgrade-041-2026-10-11](upgrade-041-2026-10-11.md) · [testing](testing.md)

Gate (RELEASE G7, first item): clean installs from each archive load exactly
one copy with the pak mounted, and the Workshop/manual conflict is detected and
explained. Also evidence for G2 (synchronous writer, no fence on a clean
install).

Rig: test install `D:\Steam\steamapps\common\Palworld`, singleplayer test
world, `tools/g7_install_matrix.py` (prepare / manual / workshop-content /
workshop on|off / wipe / status / restore). `prepare` moved the dev install,
the LogicMods pak, ManagedMods, PalModSettings.ini, mods.txt and the Workshop
item folder into `D:/PalWorkPriority-backups/g7-install-20261020-191557/`;
`restore` puts them back and checks hashes. The game was closed (checked with
tasklist) before every step.

## A. Clean manual install (Nexus archive, rc1 at 172eccf): PASS

- Nothing installed, no data files. `manual` extracted the archive: 65 files,
  the pak (sha256 4eddf38b…), `enabled.txt`.
- 19:16:53 `Pal Work Priority 0.5.0-rc1 loaded (enabled, live)`, 19:16:56
  `PWP_READY … role=authority settings=available`, world ready 19:17:54.
- One copy (one load line), pak mounted (stand numbers visible), no recovery
  fence, no "restart to edit". The synchronous writer created
  `priorities.txt` (53 lines, vanilla baseline) and `config.lua`.

## B. Manual 0.5.0 present, Workshop 0.4.1 switched on, never installed by the loader

- `ActiveModList=PalWorkPriority` added, no `ManagedMods/PalWorkPriority`.
- 19:20:54 `Pal Work Priority 0.4.1 loaded`: the loader installed the
  Workshop 0.4.1 over the manual 0.5.0 without asking (`LastInstallTimeUtc`
  17:20:50 UTC, main.lua `VERSION = "0.4.1"`). 0.5.0 never ran, so it could
  not warn. The data file was still unchanged (27 X rows); 0.4.1 drops X rows
  on its next save, which is the known 0.4.1 behaviour.
- Consequence: a manual install cannot protect itself here. The changelog and
  the Nexus page must say "use one copy: switch the Workshop copy off or
  unsubscribe before installing by hand".

## B2. Manual 0.5.0 extracted over a loader-managed 0.4.1, Workshop still on

- `manual` extracted 67 files over the managed 0.4.1. 19:25:24
  `Pal Work Priority 0.5.0-rc1 loaded`: the loader did not reinstall
  (its Info.json version is unchanged, `LastInstallTimeUtc` still 17:20:50).
- The loader still owns those file names in its InstallManifest and deletes
  them when the Workshop copy updates or is removed (G1 note). This is the
  case 0.5.0 can see: switched on, managed version differs from the running
  one.
- New `Scripts/install_check.lua` (tests/test_install_check.lua): reads
  PalModSettings.ini and `ManagedMods/PalWorkPriority/Info.json` once at
  load, plain file reads, silent when anything is unreadable or the layout is
  not the official loader layout (dedicated server).
- 19:30:26 log: `WARN Pal Work Priority 0.5.0-rc1 is installed by hand, but
  the Steam Workshop copy (0.4.1) is also switched on. …`
- Chat route tried three times (at load, 15 s after the world, from a probe
  using the G6 helper's exact calls): the engine accepted
  `SendSystemToPlayerChat` and the singleplayer chat never showed the line.
  Dropped; the warning goes on the Production Limits panel instead.
- 19:43 panel (Alt+F1): the sub line reads `Storage: All loaded bases in your
  guild. Steam Workshop copy 0.4.1 also on: use one copy.` in the warning
  colour. PASS.

## C. Clean Workshop install (Workshop archive at 0996a36): PASS, 2026-10-21

- `prepare` (state `g7-install-20261021-143803`), nothing installed, no data;
  `workshop-content` put the 0996a36 Workshop archive (66 files, no DLL) into
  the item, `workshop on`.
- 14:38:39 the loader installed it (`LastInstallTimeUtc` 12:38:39 UTC,
  managed Info.json `0.5.0-rc1`, 62 manifest entries, `"Backups": []`).
- 14:38:44 one `Pal Work Priority 0.5.0-rc1 loaded` line, 14:38:48
  `PWP_READY … settings=available`, world ready 14:39:40. No WARN, so no
  false install warning when the loader manages the running version.
- Pak mounted: the Monitoring Stand showed priority numbers (screenshot
  14:39). The synchronous writer created `priorities.txt` (vanilla baseline)
  and its `.bak`; the first start seeded the root `config.lua` from the
  shipped defaults and kept `config.migration.bak` (identical, 7808 bytes).
  No fence, no "restart to edit".

## Found while restoring: the loader renames a file in its way

`Pal/Content/Paks/LogicMods/PalWorkPriority-20261020-192050.pak.bak` (dated
19:15, the manual pak from scenario A) was left from scenario B: when the
loader installed the Workshop 0.4.1 over the manual install at 19:20:50 it
renamed the manual pak instead of overwriting it. `"Backups": []` in its
manifest does not mean nothing was kept. The `.bak` is not mounted (not a
`.pak`). Moved into `g7-install-20261020-191557/`; `restore` now moves such
files into the state folder itself.
