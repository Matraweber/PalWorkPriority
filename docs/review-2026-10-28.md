# Twelve-reviewer audit of 0.5.0 (2026-10-28)

Related: [RELEASE-0.5.0](RELEASE-0.5.0.md) · [ux-review-2026-10-21](ux-review-2026-10-21.md) · [per-item-limits-2026-10-27](per-item-limits-2026-10-27.md) · [workshop-upload-2026-10-28](workshop-upload-2026-10-28.md) · [LESSONS](LESSONS.md)

## Why and how

The user asked for an agent that rates the whole frontend for people who never used the
mod. Then they asked for "more agents for every little aspect so bug fixes and everything",
and finally for "all of them give a rating too and are very strict".

Twelve read-only reviewer agents were made (`~/.claude/agents/palworld-*.md`, outside the
repo). Each rates its area out of 10. An open P1 caps the score at 5, and two or more P1s
cap it at 4. They reviewed HEAD 3df0241, whose Lua matches tag v0.5.0 (35366bf).

UX, accessibility and panel reviewers got 13 fresh in-game screenshots
(`test-results/ux-2026-10-28/`, local): stand, panel states, and the DarnMenu options
page. DarnMenu 1.8.11 (Workshop 3769456391) was switched on in `PalModSettings.ini` for
this; the backup is `PalModSettings.ini.before-darnmenu-20261028`.

**Nothing is fixed yet. The user picks.**

## Findings by fix bundle

### A. Code P1s

Small, each with a test.

1. **DarnMenu can stop the mod from starting.** The menu allows "Seconds between
   passes" from 2, but validation needs 5 or more (`darnmenu.lua:80-81`,
   `configuration.lua:50`). Main.lua then logs "did not start" on every launch.
   - Found by: test coverage and persistence.
   - Fix: set the minimum to 5, and make the menu overlay skip any value that fails
     validation, with a warning.
2. **Mod off, `pwp restore` and dry run never release held rocks.** The rocks stay
   NotWorkable until a reload. On a server that means days. `scheduler.restore` never
   calls `item_sources`.
   - Found by: test coverage, engine, scheduler.
   - Fix: add `item_sources.release_all` and call it from restore.
3. **A Stone Pit at a stone-only base keeps running past the Stone limit** while another
   Mining item is short guild-wide. The cause is `type_capped`, which checks
   `cap_reached` before `item_wanted` (`scheduler.lua:1099`).
   - Found by: scheduler.
   - Fix: with per-item on, decide Mining by `item_wanted` alone, and count an
     unreadable product under a limit as wanted.
4. **Robustness gaps in `item_sources`:**
   - A partial works read forgets held rocks.
   - `wanted[nil]` throws.
   - A failed product read is cached as false.
   - A failed read falls back to group limits for that pass.
   - A base with no Pals blanks the verdict.

   Found by: scheduler, coverage, performance, engine.
5. **A client on a server without the mod, or on a 0.4.1 server, gets "?" in every
   stand cell** and the vanilla checkbox hidden for the whole session
   (`ui.lua:1017-1075`). A test pins this behaviour (`test_ui_integration.lua:985`).
   - Found by: onboarding and multiplayer.
   - Fix: give the stand back to the game.
6. **No cap on rules per guild since the unlock.** At 501 rules every member of that
   guild is stuck "connecting", and the state survives restarts.
   - Found by: multiplayer, coverage, engine.
   - Fix: `apply_set` refuses rule 501 with `too_many_limits`.
7. **`pwp rocks` has no authority gate.** It calls server-only functions on client
   proxies. Found by: engine.

### B. Panel input safety

Found by: panel bugs, UX, accessibility.

1. **Bound keys fire while a text box has focus.**
   - Left or Right in the amount editor saves a half-typed number.
   - Enter in the search box creates a limit on the first match.
2. **The keyboard/pad selection is a list position.** When the "change base" button or
   Confirm/Cancel appear, it drifts, so two "raise" presses can delete rule 1. Show all
   can turn into a create. Enter on Next bounces between pages 1 and 2.
   - Fix: re-find the selection by what it points at.
3. **A click on an item tile while stock is unavailable creates a limit of 100.** At
   50,000 or more it seeds an already-reached limit.
4. **One click on an item tile creates a limit.** Fix: two clicks, where the first click
   shows what the limit stops and the amount (UX P1-1).
5. **Remove: the notice outlasts the arm.** The notice lasts 7 s, the "Sure?" arm 4 s.
   The prompt also does not name the item. "Sure?" has 3.8:1 contrast.
6. **Smaller panel bugs:**
   - The picker cache ignores which base it shows.
   - A new limit is not followed.
   - "Change base" cannot be reached by keyboard or pad.
   - An old notice survives a reopen.
   - Keyboard users cannot reach Remove (bind Delete).

### E. Accessibility

Contrast is measured from screenshots. Several ratios claimed in `panel.lua` comments
are wrong: amber is 4.29:1, not 7.3:1.

- The stand legend reads 1.4-2.4:1 on grass. Fix: a dark backing and 14 pt (P1).
- On a selected tile, "has a limit" is shown by colour only. "Green items have one" also
  relies on colour.
- The 9-10 pt sub-labels are too small and faint.
- `ROW_SEL` fails for text.
- Controller hints still say Esc and ALT+F2.
- The Steam Deck is untested, and text entry there needs a keyboard.

### F. Performance

- The pass reads `camp_works` twice per camp whenever Mining has limits. That is about
  +5 ms for 2 camps, so roughly 25 ms instead of 20.
- Fix: read once per camp and share it. Then take a `pwp perf` reading.
- The panel redraw has never been captured.

### G. Tooling

- The upload guard reads a `.workshop.json` value that is one release behind. Use the
  live `Info.json` instead.
- `--submit` treats "Submitted, but failed to ..." as a failure.
- The restart macro's `MenuOpen` was never sampled with the stand open. Fix: refuse to
  start if the menu already looks open.
- The guards are `assert`s, which `python -O` removes.
- `check` should default to the staged version.

### H. Larger, could wait for 0.5.x

These are open decisions, not oversights.

- A client limit verdict needs protocol schema 5. Without it, clients show "No count
  yet" all session. The minimum alternative is honest client wording plus a DECISIONS
  entry.
- A notice when the config was reset by an upgrade.
- A notice when the pak is missing.
- Detecting a second UE4SS layout.
- Options page wording and help:
  - "Lowest rank worth dedicating" reads like the 1-5 priority.
  - "Ceilings" should be "limits".
  - One name for Alt+F2.
  - Help for each option.
- Real Steam Deck and Steam Input runs.
- A G5 capture with Mining limits.
