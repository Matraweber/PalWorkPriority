## Dedicated server (GPortal "RAM") with this PC as client

- **Install.**
  - The file panel listed existing folders as empty for a while. The server log
    proved the files were there. After a retry it listed correctly again.
  - `Scripts` was renamed to `Scripts-before-a051f02`. `Scripts.zip` (60 files at
    its root) was uploaded with Overwrite and unpacked with the plain "UNZIP". Key
    file sizes match the commit.
  - Restart: `PWP_READY` at 17:07, no warning.
- **Group row on the client.** The client set Lumbering Wood 1. The client row
  read **"Limit reached"** from the server's verdict (s05), and `pwp net` showed
  `verdicts=1`. This closes round-2 P3-1, where only a per-item row had been seen.
- **Bug found.** After the client raised the limit (17:11:03), the row dropped to
  "Waiting for the server's count" and never got a count again. 45 s later
  `request_ids_issued=7`, `verified=false`, and the server logged nothing unusual.
  - Fixed in `fix/net-r3` (8687524).
  - **Panel base reset:** `pwp limit` read stock with no base, which reset the
    panel's base and its request in flight.
  - **In-flight count:** a count that was already on its way was stripped of its
    verdict.
  - **Request spacing:** the follow-up request went out 1 s after the last one,
    and the server refuses requests less than 1 s apart. Requests now keep 1.5 s.
- **Retest of the fix.** Only `net.lua` was uploaded (Overwrite, 98.79 KiB), then
  the server and the game were restarted. Wood 1 showed "Limit reached" at 17:27:48.
  The raise to 9,999,999 was at 17:28:24, and **by 17:28:30 the client had a
  verified count with verdicts**, so the row read "Below limit" with storage 7,649
  (s09). The test limit was cleared ("Deforest Wood cleared by a player").
- **Server warnings seen at the join** (17:27), not investigated:
  - "some work could not be typed"
  - "ignoring repeated announcements from one player, too many at once"
