# Isolated lifecycle epoch experiment

Nothing here installs, deploys, imports production Scripts, or controls the game.

Pinned source inspected: `test-results/native-helper-prerequisites-2281fa31/source/UE4SS/src/Mod/LuaMod.cpp`, registration at 2417–2526 and callbacks at 6437–6540. LoadMap pre/post receive engine/current-world/FURL/pending-game/error arguments, but no original success result. A boolean return invokes `TrySetReturnValue`; nil leaves it alone. InitGameState pre/post receive a game-mode wrapper and request zero results. All experiment callbacks discard arguments and explicitly return nil. Successful pinned registration returns no values; presence/registration success cannot prove that a hook actually fires on a given route.

`save_lifecycle_epoch.lua` requires all four registrars. Missing functions, throwing registrations (even after partial registration), explicit registration failure, or epoch/depth exhaustion close the gate. Installation is one-shot; partially registered callbacks cannot reopen it. Every pre revokes readiness and advances the epoch before diagnostics. Unexpected posts also invalidate. Counters saturate, depths are bounded, and exhausted epochs never wrap. There is no retained callback history or outstanding-token registry.

After a paired InitGameState and completion of any enclosing LoadMap, `candidate()` returns an opaque Lua function carrying a fixed numeric epoch. `authorize(candidate, verifier)` requires a fresh verifier returning exactly true; post events alone never authorize. The verifier must establish current authority, identity and active storage independently. `admit()` returns the current immutable token only while ready. Capture that token when dispatching work and use `accepts(captured)` on the game thread immediately before applying its completion. Never fetch a replacement token for an old completion. Do not yield between the check and application. This rejects obsolete replies; it does not cancel native IO, undo accepted writes, release journal ownership, or prove durability. The token is local to its controller and must not be serialized or passed to a native worker. Keep one controller for the experiment lifetime; replacing it is not a native ownership protocol.

All methods, verifier calls and diagnostics are synchronous on the game thread. A fresh controller starts closed and late attachment without an observed initialization stays closed. Failed verification or explicit revocation requires another observed initialization before re-authorization. There are no engine queries, polling timers or automatic readiness heuristics.

## Next-restart diagnostic observation

From a separately prepared development harness, manually load `experiments/save_lifecycle_epoch_observer.lua` with `dofile` and call `start(_G, logger)` once, before world entry. `logger` receives only strings; the driver returns installation status and a copied status accessor, with no admission API. It records sequence, event name, epoch, transition depths and readiness, capped at 256 callback lines by default (optional third argument: 1–4096). Logging failure is contained. Loading the driver alone does nothing. No harness has been installed by this change.

For the user's manual A → title → B test, correlate these lines with external UI/session markers. The observer deliberately does not inspect wrapper addresses, URLs, directories, role or save IDs and cannot identify A/B by itself. Check whether a pre callback arrives before any old completion could be applied, and whether initialization/post ordering is as expected. A callback trace is evidence for that tested route only. Do not infer seamless travel, client disconnect, dedicated-server behavior, all error paths, teardown, missing hooks, or concurrency ordering from these mocks. Native ordering and actual callback availability remain live-validation work.

User-reported live observation (2026-10-04): brand-new B gameplay at level 1 has a new GameState directory beginning `D869`, role 3, and matching current-chain ownership, while selected save directory remains nil and `loaded_world=false` after cinematic/gameplay. Existing A has agreeing selection and loaded=true. The new-world case remains unverified for active storage; loaded=false is not evidence of a false role. Normal title/reload of B subsequently has selected+loaded=true and passed phase 3. A returned ready and phase 5 completed at 13:42:58 UTC, with stand numbers verified at 13:44 UTC. Lifecycle completion must not fill in absent storage evidence or open this gate.
